# CK3 Localization Manager — продуктовая документация

**Версия документа:** 1.0
**Дата:** 26.07.2026
**Статус:** проработанная концепция, готовая к передаче в разработку (этап 1)

---

## 1. Продукт одним абзацем

**CK3 Localization Manager** — настольное приложение для Windows, которое само находит все установленные моды Crusader Kings 3 из мастерской Steam, показывает, на какие языки каждый мод переведён и насколько полно, помогает перевести недостающее (встроенным машинным переводом или через обмен файлами с любой LLM), а результат записывает **прямо в мод — добавленной папкой русской локализации** (или, по желанию, отдельным локальным модом-переводом), никогда не изменяя файлы автора и не теряя работу при обновлениях: всё хранится в базе приложения и восстанавливается в один клик. Главное отличие от «просто переводчика»: приложение **живёт вместе с библиотекой модов** — замечает обновления, показывает, какие строки появились или изменились у автора, и не даёт переводу молча устареть.

Формула ценности: *не «перевести мод один раз», а «поддерживать перевод актуальным всю жизнь мода».*

---

## 2. Проблема, которую решаем

1. **Модов много, русского мало.** В библиотеке типичного игрока 100–200 модов; у большинства есть только английская локализация, русская — у меньшинства.
2. **Перевод вручную мучителен.** Файлы локализации разбросаны по вложенным папкам, их десятки на мод, формат капризный (кодировка, кавычки, игровые коды внутри текста).
3. **Обновления всё ломают.** Steam перезаписывает папку мода при каждом обновлении: перевод, положенный внутрь мода без резервной копии, погибает безвозвратно. А любой перевод со временем тихо устаревает: автор добавил 30 строк, игрок видит в игре английские огрызки и не понимает почему.
4. **Даже «родные» переводы отстают.** Авторы модов часто обновляют английский текст и забывают про остальные языки. Снаружи это никак не видно — только в игре.
5. **Существующие инструменты закрывают лишь кусок.** Есть скрипты «прогнать папку через переводчик», есть редакторы, но нет менеджера всей библиотеки с отслеживанием версий, историей и безопасной публикацией результата.

### Кто пользователь

| Персона | Что хочет | Что для него критично |
|---|---|---|
| **Игрок** (основная) | Играть на русском во все свои моды, потратив минимум усилий | Кнопка «сделай хорошо», понятные статусы, ничего не сломать |
| **Переводчик-энтузиаст** | Делать качественные переводы и поддерживать их | Редактор, глоссарий, сравнение версий, экспорт для автора мода |
| **Автор мода** (косвенная) | Получить готовую папку локализации от сообщества | Экспорт «дерева для автора» в правильном формате |

Клиент проекта — по профилю ближе всего к «игроку с амбициями переводчика»: понимает устройство модов и локализации, но не программирует. Поэтому весь интерфейс и вся документация строятся по принципу: **никаких терминов без объяснения, никаких действий без предпросмотра, никаких изменений без резервной копии.**

## 3. Железные принципы (не обсуждаются)

Эти правила — фундамент. Любая функция, которая им противоречит, не делается.

1. **Файлы автора мода неприкосновенны, а база приложения — источник истины.** Приложение никогда не изменяет и не удаляет файлы автора в `steamapps\workshop\content\1158310` — оно только **добавляет** собственные папки перевода (режим «внутрь мода», раздел 5) либо пишет в отдельный локальный патч-мод. Всё добавленное восстановимо из базы в один клик: даже если Steam сотрёт это при обновлении, работа не теряется.
2. **Файлы локализации читаются и пишутся «без потерь».** Если пользователь ничего не менял, файл после чтения и записи совпадает с исходным **байт в байт** (кодировка, переводы строк, комментарии, порядок, отступы). Обычные YAML-библиотеки для этого не годятся — нужен собственный построчный парсер (подробно — раздел 8).
3. **Игровые коды в тексте неприкосновенны.** Конструкции вида `$KEY$`, `[Character.GetFirstName]`, `@icon!`, `#T ... #!`, `\n` защищаются перед любым машинным переводом и проверяются после (раздел 11).
4. **Машинный перевод ≠ готовый перевод.** У каждой строки есть статус; машинная строка попадает в игру, но помечена как «не проверена человеком».
5. **Ключ — главная единица учёта.** Перевод привязан к ключу локализации, а не к файлу: автор может переложить ключ в другой файл — перевод не теряется.
6. **Никаких молчаливых решений в спорных ситуациях.** Дубликат ключа, расхождение языка в имени файла и заголовке, «лишние» ключи в русском — всё это показывается пользователю как диагностика, а не «исправляется» автоматически.
7. **Любая запись — атомарна и с резервной копией.** Сначала полностью пишем во временный файл, проверяем, сохраняем копию старого, затем подменяем.
8. **История хранится вечно (в разумных пределах).** Для каждой замеченной версии мода сохраняется снимок локализации — иначе невозможно определить, что именно изменилось и какие переводы устарели.

## 4. Как это работает — картина целиком

Простыми словами, приложение — это конвейер из шести станций:

```
 ┌────────────────────────────────────────────────────────────────────┐
 │ 1. СКАНЕР        находит Steam, все библиотеки, все моды CK3,      │
 │                  читает названия, версии, языки локализаций        │
 └───────────────┬────────────────────────────────────────────────────┘
                 ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 2. АНАЛИЗАТОР    для каждого мода: какие языки есть, сколько       │
 │                  ключей, чего не хватает в русском, что устарело,  │
 │                  где ошибки в самих файлах мода                    │
 └───────────────┬────────────────────────────────────────────────────┘
                 ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 3. АРХИВ         снимок каждой версии локализации каждого мода;    │
 │   (история)      именно он позволяет после обновления точно        │
 │                  сказать «12 новых строк, 7 изменённых»            │
 └───────────────┬────────────────────────────────────────────────────┘
                 ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 4. ПЕРЕВОД       три пути, можно смешивать:                        │
 │                  а) встроенные переводчики (DeepL, Google, LLM…)   │
 │                  б) экспорт файла для внешней LLM → импорт обратно │
 │                  в) ручное редактирование в редакторе              │
 └───────────────┬────────────────────────────────────────────────────┘
                 ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 5. СБОРЩИК       пишет перевод внутрь мода (папка russian)         │
 │                  или отдельным патч-модом — на выбор (раздел 5)    │
 └───────────────┬────────────────────────────────────────────────────┘
                 ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 6. СТОРОЖ        следит за обновлениями модов; после обновления    │
 │                  прогоняет анализ заново и сообщает, что делать    │
 └────────────────────────────────────────────────────────────────────┘
```

Приложение состоит из **ядра** (вся логика, работает и без окна — из командной строки) и **графической оболочки**. Это позволит позже добавить автозапуск по расписанию, интеграции и т.п., не переписывая логику.

## 5. Ключевое продуктовое решение: куда записывается перевод

По решению клиента у приложения **два режима записи** результата; режим выбирается в настройках проекта (и глобально по умолчанию). В обоих режимах база приложения остаётся источником истины: любой записанный перевод можно восстановить в один клик.

### 5.1. Режим «Внутрь мода» (по умолчанию)

Приложение **добавляет** в папку мода из мастерской недостающую русскую локализацию, никогда не изменяя и не удаляя файлы автора:

```
steamapps\workshop\content\1158310\2507209632\
└── localization\
    ├── english\                          ← файлы автора: не трогаем
    │   ├── EPE_common_l_english.yml
    │   └── EPE_game_rules_l_english.yml
    ├── russian\                          ← создаём: наши переводы,
    │   ├── EPE_common_l_russian.yml         имена зеркалят исходные
    │   └── EPE_game_rules_l_russian.yml
    └── replace\
        └── russian\                      ← создаём только если нужно
            └── EPE_fixes_l_russian.yml      переопределить строки
                                             неполного родного русского
```

Плюсы: перевод работает сразу (мод уже включён в плейсет), в лаунчере нет лишних строк, ничего не нужно подключать и упорядочивать.

Цена этого режима — и как она оплачена:

- **Steam стирает добавленные файлы при каждом обновлении мода** (а иногда — при проверке целостности файлов). Это штатная ситуация, а не катастрофа: приложение замечает пропажу при следующем запуске, сверяет новую версию локализации со снимком и сообщает: «Перевод восстановлен: 145 строк. Новых строк у автора: 12 — доперевести?». Не изменившиеся строки восстанавливаются автоматически (настраивается), новые и изменённые проходят обычный цикл перевода.
- В чужую папку записываются только сами файлы локализации. Служебные данные (статусы, история, привязка к версии) живут в базе приложения — в папке мода не появляется ничего лишнего.

### 5.2. Режим «Отдельный патч-мод» (по выбору)

Для случаев, когда перевод должен переживать обновления Steam без восстановления, или когда переводом планируется делиться, приложение создаёт отдельный локальный мод:

```
Documents\Paradox Interactive\Crusader Kings III\mod\
├── ck3loc_2507209632_russian.mod          ← «паспорт» мода для лаунчера
└── ck3loc_2507209632_russian\
    ├── descriptor.mod
    ├── .ck3loc\
    │   └── manifest.json                  ← служебные данные приложения (см. 5.4)
    └── localization\
        └── replace\
            └── russian\
                ├── EPE_common_l_russian.yml
                └── EPE_game_rules_l_russian.yml
```

Правила режима: имя в лаунчере — по шаблону **«[RU] {Название мода}»**; патч-мод должен стоять в плейсете **после** оригинала; папка `replace` в CK3 переопределяет ключи с приоритетом — так наш перевод «побеждает» строки оригинального мода. На каждый мод-источник — свой патч-мод (не единый пак): отписка или обновление одного мода не трогает остальные переводы, а переводом одного мода можно поделиться, просто отдав папку. Опция «собрать все переводы в один пак» — этап 6.

### 5.3. Два режима сборки содержимого

- **Полный перевод** — записываются все ключи исходного языка. Используется, когда русского в моде нет вообще.
- **Дельта** — только недостающие и исправленные строки; «родные» русские строки мода продолжают работать сами. Используется, когда русский в моде есть, но отстаёт. Безопаснее: исправления автора мода не затираются нашими старыми копиями.

Приложение выбирает режим само (есть русский в моде → дельта; нет → полный) и показывает выбор пользователю с возможностью переключить.

### 5.4. Служебные данные и внешние правки

В режиме патч-мода внутри него лежит `.ck3loc\manifest.json` — маленький файл с данными: из какой версии мода-источника собран перевод, когда, какие ключи и с какими статусами. Он позволяет восстановить связь «патч ↔ источник» и историю статусов после переустановки приложения или переноса на другой компьютер. Игра эту папку игнорирует.

В режиме «внутрь мода» ту же роль играет база приложения: при каждом сканировании записанные файлы сверяются с базой, поэтому ручные правки в блокноте обнаруживаются и предлагаются к принятию или откату (сценарий H), а потеря базы не фатальна — записанные файлы читаются обратно как «перевод без истории».

### 5.5. Экспорт «для автора мода»

Отдельная функция: выгрузить готовую папку `localization\russian\` (без `replace`, в структуре, которую автор положит прямо в свой мод) плюс сопроводительный текстовый файл со списком ключей. Это подарок автору мода — и способ сделать перевод «официальным». Это именно экспорт, не рабочее место: приложение продолжает вести перевод у себя.

## 6. Сквозные пользовательские сценарии

Это ядро продуктовой логики: как приложение ведёт себя в жизни, шаг за шагом.

### Сценарий A. Первый запуск

1. Приложение ищет Steam (реестр Windows → `libraryfolders.vdf` → все библиотеки на всех дисках). Если не нашло — просит указать папку вручную.
2. Находит папку `workshop\content\1158310`, сканирует все моды. Прогресс показывается («Просканировано 118 из 186…»), сканирование не блокирует окно.
3. Показывает **Главный экран** со сводкой: сколько модов, у скольких нет русского, у скольких он неполный, где есть ошибки в файлах.
4. Первое сканирование одновременно создаёт **начальные снимки** всех локализаций — это точка отсчёта для будущих сравнений.
5. Ненавязчивая подсказка: «Начните с любого мода без русского — вот 5 самых маленьких, на них удобно попробовать».

Здесь же приложение находит локализацию самой игры (папка установки CK3) и индексирует ванильные русские строки — они пригодятся как готовые переводы (раздел 12).

### Сценарий B. Перевести мод, у которого русского нет вообще

1. Пользователь открывает карточку мода → видит: «Русский: 0%. 1 240 строк на перевод. Из них 96 совпадают с ванильными строками игры (переведутся бесплатно и мгновенно), для 31 есть готовый перевод в вашей памяти переводов».
2. Нажимает «Создать русский перевод». Приложение создаёт **проект перевода** (мод + пара языков EN→RU) и предлагает путь:
   - **Встроенный перевод** — выбрать провайдера (DeepL / Google / Azure / LLM по API / офлайн Argos), посмотреть оценку объёма (сколько строк реально пойдёт в API после вычета ванили и памяти переводов), запустить.
   - **Внешняя LLM** — экспортировать файл-задание (раздел 13), перевести где угодно, импортировать обратно.
   - **Вручную** — просто открыть редактор.
3. После перевода все строки получают статус «Машинный перевод — не проверен». Пользователь может проверять их в редакторе (может и не проверять — его право).
4. Нажимает «Записать перевод». Приложение показывает предпросмотр (какие файлы будут созданы, сколько ключей) и записывает русскую папку прямо в мод (режим по умолчанию) — включать ничего не нужно, мод уже в плейсете. Если выбран режим патч-мода — собирает его и напоминает поставить в плейсете после оригинала.
5. В игре — русский текст. Готово.

### Сценарий C. Дописать неполный «родной» русский перевод мода

1. Карточка мода показывает: «Русский: 91%. Пропущено 2 ключа. 6 ключей есть только в русском (возможно, намеренно — требуется взгляд человека)».
2. Пользователь видит список пропущенных строк с английским оригиналом, переводит их (любым из трёх путей).
3. Сборка идёт в режиме **дельты**: записываются только эти 2 строки.
4. «Лишние» русские ключи никогда не удаляются автоматически — они помечены «только в целевом языке» и ждут решения человека (чаще всего это переопределения ванильных строк или наследие старых версий).

### Сценарий D. Мод обновился (главный сценарий продукта)

1. Сторож замечает: у мода изменилось время обновления Steam / изменились файлы. Запускается переанализ **именно локализации** (быстро, по хешам).
2. Пользователь видит уведомление в приложении:

   > **Expanded Personality Traits обновился.**
   > Локализация изменилась: да.
   > Новых строк: 12 · Изменённых: 7 · Удалённых: 3.
   > Ваш перевод: 12 отсутствуют, 7 устарели, 145 актуальны.
   > [Показать изменения] [Доперевести]

3. «Показать изменения» открывает список: для изменённых строк — три колонки: *английский, каким он был при переводе* | *английский сейчас* | *ваш русский*. Так сразу видно, что именно поменял автор и надо ли трогать перевод (иногда автор просто исправил опечатку — тогда одна кнопка «перевод всё ещё верен»).
4. «Доперевести» — переводятся только 12 новых + 7 устаревших строк, после чего перевод записывается заново. Удалённые автором ключи выводятся из записи (но остаются в истории и памяти переводов). В режиме «внутрь мода» обновление Steam заодно стёрло наши файлы — приложение говорит об этом в том же уведомлении и автоматически восстанавливает не изменившиеся 145 строк.
5. На всё — 2–3 минуты вместо ручного сравнения сотен строк.

### Сценарий E. Проверить чужой мод, не переводя его

Пользователь просто открывает карточку любого мода и видит анализ: какие языки, полнота каждого относительно английского, синтаксические ошибки в файлах, дубликаты ключей. Это работает **для всех модов всегда**, независимо от того, ведёт ли пользователь их перевод. Режим «только чтение» — отдельная ценность: можно, например, написать автору мода «у тебя во французском 40 строк отстало».

### Сценарий F. Обмен с внешней LLM (например, с чат-ботом без API)

1. В карточке проекта: «Экспорт для LLM» → выбирается, что экспортировать (всё непереведённое / только устаревшее / выбранные строки) → создаётся файл-задание (формат — раздел 13) + готовая текстовая инструкция-промпт, которую можно вставить в чат вместе с файлом.
2. Пользователь скармливает файл любой LLM, получает файл с переводами.
3. «Импорт» → приложение проверяет каждую строку: не изменился ли исходник с момента экспорта, целы ли игровые коды, на месте ли идентификаторы. Отчёт: «Принято 214, отклонено 3 (повреждён игровой код — показать), пропущено 1 (исходник успел обновиться)».
4. Отклонённые строки остаются в списке недоделанного — их можно поправить вручную или отправить на повторный перевод.

### Сценарий G. Пользователь отписался от мода / мод удалён из Workshop

1. Сканер замечает: папки мода больше нет. Мод помечается «не установлен», всё связанное (проект, история, память переводов) сохраняется.
2. В режиме «внутрь мода» перевод исчез вместе с папкой мода — но всё хранится в базе, терять нечего. Если был создан патч-мод, он **не удаляется автоматически** (принцип №6): «Мод-источник удалён. [Отключить патч] [Удалить патч (с резервной копией)] [Оставить как есть]».
3. Если мод вернётся (переподписка) — история на месте, перевод записывается заново одной кнопкой.

### Сценарий H. Записанные файлы правили руками извне

При сканировании приложение сверяет записанные им файлы (в папке мода или в патч-моде) с базой. Расхождение → диагностика «Внешнее изменение»: показать различия, «принять в базу» (правки становятся официальными, статус строк — «отредактировано вручную») или «восстановить из базы». Молча перезаписывать ручной труд нельзя.

### Сценарий I. Пакетный режим «переведи всё»

На главном экране: «57 модов без русского. [Перевести все…]». Мастер: выбор провайдера → оценка объёма и примерной стоимости по тарифам провайдера **до** запуска → очередь заданий с прогрессом, паузой и продолжением после сбоя. Итоговый отчёт по каждому моду. Это витринная функция для персоны «игрок»: вечером запустил — утром вся библиотека на русском.

## 7. Жизненный цикл строки перевода

Каждая переводимая строка — маленький объект со своей судьбой. Это сердце логики приложения.

### 7.1. Статусы (что видит пользователь)

```
                    ┌──────────────┐
                    │ Не переведено│ ← новый ключ у автора мода
                    └──────┬───────┘
              перевод API / │ \ импорт из LLM / ручной ввод
                            ▼
                    ┌──────────────┐
                    │  Машинный    │ ← в игру попадает, но помечен
                    │ (не проверен)│
                    └──────┬───────┘
             человек глянул │
                            ▼
                    ┌──────────────┐
                    │  Проверено   │
                    └──────┬───────┘
     автор мода изменил английский текст?
              │                         │
              ▼ да                      ▼ нет
      ┌──────────────┐          остаётся «Проверено»
      │   Устарело   │──────────────────┐
      └──────────────┘   пользователь   │
                         подтвердил или ▼
                         перевёл заново → снова «Проверено»
```

Дополнительные особые статусы (не этапы, а «флажки поверх»):

| Флажок | Что значит | Что предлагает приложение |
|---|---|---|
| **Конфликт** | Автор изменил английский, И пользователь менял русский — оба после последней сверки | Показать три версии, человек решает |
| **Осиротевший** | Ключ удалён из английского, но русский перевод существует | Вывести из записи, сохранить в истории |
| **Только в целевом** | Ключ есть в русском моде, но нет в английском | Ничего не делать без человека |
| **Ошибка кодов** | Игровые коды в переводе не совпадают с оригиналом | Блокировать строку в сборке, показать различия |
| **Дубликат** | Один ключ встречается несколько раз в моде | Показать все вхождения |
| **Совпадает с оригиналом** | «Перевод» дословно равен английскому | Подсветить как подозрительный (LLM поленилась) |
| **Внешняя правка** | Записанный файл изменён вне приложения | Принять или откатить |
| **Без истории** | Русский перевод существовал до знакомства с приложением | Считается непроверенным, но рабочим |

### 7.2. Как приложение понимает, что перевод устарел (трёхстороннее сравнение)

Для каждой переведённой строки хранится не только сам перевод, но и **английский текст, каким он был в момент перевода** (точнее — его «отпечаток», хеш). После обновления мода:

- английский не изменился → перевод **актуален**;
- английский изменился, русский не трогали → перевод **устарел**;
- изменились оба → **конфликт**, решает человек;
- английского ключа больше нет → перевод **осиротел**;
- появился новый английский ключ → **не переведено**.

Без сохранённого «английского на момент перевода» эта логика невозможна в принципе — вот зачем нужен архив снимков (станция 3). Простые инструменты сравнивают только *наличие* ключей и потому не видят устаревания.

Важно: отпечаток считается по **значению строки**, а не по файлу целиком. Автор передвинул строки, добавил комментарий, поменял переносы строк — переводы не считаются устаревшими.

## 8. Чтение и запись файлов локализации (почему тут нельзя схалтурить)

Формат CK3 *похож* на YAML, но им не является. Реальные файлы содержат:

- кодировку UTF-8 с BOM (обязательна — без неё игра не прочитает файл);
- строки вида `key:0 "Текст"` и `key: "Текст"` вперемешку (цифра — устаревший атрибут, встречается повсеместно);
- комментарии `#`, пустые строки, нестандартные отступы;
- кавычки внутри кавычек, коды `\n`, игровые конструкции;
- иногда — откровенно битые строки, которые игра тем не менее «прощает».

Стандартная YAML-библиотека всё это переформатирует или отвергнет. Поэтому пишется **собственный построчный парсер**, который знает пять видов строк: заголовок языка (`l_english:`), запись (ключ + значение), комментарий, пустая строка, нераспознанная строка. Каждая строка хранит свой исходный текст; при записи неизменённые строки выводятся как были, у изменённых заменяется только значение в кавычках.

**Главный тест ядра** (пишется раньше любой другой функции): взять реальные файлы из десятков модов, прочитать, записать без изменений — результат обязан совпасть с исходником байт в байт. Этот тест — критерий готовности этапа 1 и вечный страж от регрессий.

Нераспознанные строки не считаются катастрофой: они сохраняются как есть, попадают в диагностику мода («синтаксическая ошибка в строке N») и никогда не переводятся автоматически.

## 9. Что считать «версией мода»

Поле `version` в descriptor.mod авторы забывают обновлять, а `supported_version` — это совместимость с игрой, не версия мода. Поэтому приложение строит **составной отпечаток**:

1. время обновления по данным Steam (Workshop API + локальный файл `appworkshop_1158310.acf`);
2. версия из descriptor.mod (как справочная информация);
3. хеш всех файлов локализации (изменилась ли локализация — самый важный сигнал);
4. хеш остального дерева файлов (изменился ли мод вообще — считается в фоне, неторопливо).

Уведомление пользователю всегда формулируется содержательно: не «версия 2.0 → 2.1», а «локализация изменилась: 12 новых строк, 7 изменённых» (сценарий D). Если мод обновился, но локализация не тронута — уведомление тихое, в общем списке, без призыва к действию.

Скорость: при повторном сканировании сначала сравниваются размер и дата файлов, хешируются только подозреваемые. Полное сканирование библиотеки из ~200 модов должно укладываться в секунды, а не минуты.

## 10. Обнаружение модов и языков — правила и краевые случаи

- **Несколько библиотек Steam** на разных дисках — поддерживаются (через `libraryfolders.vdf`).
- **Название мода** берётся из descriptor.mod; если его нет или он бит — запрашивается по ID через открытый Workshop API; если и это недоступно (офлайн) — показывается ID папки. Хранятся оба названия (авторское и воркшопное), различие — в диагностику.
- **Поиск файлов локализации** — рекурсивный по всему дереву `localization\**\*.yml`, включая обе формы replace (`localization\replace\russian\...` и `localization\russian\replace\...`) и любую глубину вложенности.
- **Язык файла** определяется по трём признакам: заголовок `l_russian:` внутри (главный), суффикс имени `_l_russian.yml`, папка `\russian\`. Расхождение — предупреждение в диагностике, для работы берётся заголовок.
- **Список языков игры** не зашивается навсегда: он читается из установленной CK3 (сейчас их девять: английский, французский, немецкий, испанский, русский, упрощённый китайский, корейский, польский, японский), встроенный список — резерв на случай, если игра не найдена.
- **Моды не из Workshop** (локальные, из папки Documents) в первой версии только отображаются в списке; полная поддержка их перевода — этап 6. Патч-моды, созданные самим приложением, распознаются по манифесту и в списке «модов на перевод» не участвуют.
- **Исходный язык — любой, не только английский.** По умолчанию английский, но если его нет или он сам неполный, приложение предлагает в качестве источника самый полный язык мода (бывают моды с «родным» немецким, китайским, русским). Настраивается для каждого проекта; целевой язык тоже не ограничен русским. Дополнительно есть режим «объединение всех языков» — чтобы найти ключи, которые есть хоть где-то, но пропущены и в источнике, и в цели.

## 11. Защита игровых кодов при переводе

Строки CK3 нашпигованы служебными конструкциями, которые нельзя переводить:

| Конструкция | Пример | Что это |
|---|---|---|
| `$...$` | `$k_france$` | подстановка другой строки локализации |
| `[...]` | `[Character.GetFirstName]` | вызов игровой функции (внутри бывают вложенные скобки и параметры) |
| `@...!` | `@epe_icon_epe_rule!` | иконка |
| `#X ... #!` | `#T Заголовок#!` | форматирование (жирный, цвет…), теги парные |
| `\n` | — | перенос строки |

Порядок работы при любом машинном переводе:

1. Разобрать строку маленьким лексером (не одной «умной» регуляркой — вложенные скобки её ломают).
2. Заменить каждый код на нейтральный маркер-заглушку (`⟦T1⟧`, `⟦T2⟧`…), который переводчики не трогают.
3. Перевести только человеческий текст.
4. Вернуть коды на место.
5. Проверить: набор `$...$` совпадает, набор `[...]` совпадает, иконки целы, парные теги сбалансированы, кавычки экранированы, нет настоящего переноса строки внутри записи.

Строка, не прошедшая проверку, получает флажок «Ошибка кодов», в запись не попадает (вместо неё — оригинал или прежний перевод) и ждёт человека. Та же проверка выполняется при импорте из внешней LLM и при ручном редактировании (мягко: подсветка прямо в редакторе).

## 12. Экономия и качество: память переводов, ваниль, глоссарий

Перед отправкой строки внешнему переводчику приложение по порядку проверяет:

1. **Ванильную локализацию CK3.** Если мод дословно использует строку из игры (названия титулов, стандартные описания и т.п.) — берётся официальный русский перевод Paradox: бесплатно, мгновенно, терминологически идеально. По опыту это закрывает заметный процент строк.
2. **Память переводов** — все ранее утверждённые пары «английский → русский» из всех проектов пользователя. Тот же текст в другом моде переводится один раз.
3. **Похожие строки** (нечёткое совпадение) — предлагаются как подсказка в редакторе, автоматически не подставляются.

**Глоссарий** — словарь терминов с уровнями: глобальный CK3 (Realm → Держава, Holding → Владение, County → Графство…), уровень конкретного мода, уровень проекта. Режимы термина: обязательный / предпочтительный / не переводить. Глоссарий передаётся провайдерам, которые его поддерживают (DeepL, LLM), и используется в проверке качества («в строке есть Realm, а в переводе нет Державы — подсветить»). Стартовый глобальный глоссарий CK3 поставляется вместе с приложением.

**Контекст для LLM-перевода.** Тип строки часто виден по ключу: `*_desc` — описание, `rule_*` — правило игры, ключи с `title` — названия. Это передаётся LLM как подсказка («переводи как краткое название кнопки», «переводи как описание в подсказке») — заметно поднимает качество. Это эвристика-подсказка, не жёсткое правило.

### Провайдеры перевода

Приоритет по решению клиента: сначала классические машинные переводчики, затем LLM. В архитектуре все провайдеры равноправны и подключаются одинаково — через единый внутренний интерфейс.

| Провайдер | Очередь | Особенности |
|---|---|---|
| Google Cloud Translation | Волна 1 | Массовый, много языков; требует облачный аккаунт |
| Yandex Translate | Волна 1 | Традиционно силён в русском; ключ через Яндекс Облако |
| DeepL API | Волна 1 | Качественный массовый МП; глоссарии, контекст; есть бесплатный тариф |
| LLM по API (Claude, OpenAI-совместимые) | Волна 2 | Лучшее качество со стилем и глоссарием; настраиваемый промпт |
| Azure Translator | Опционально | Есть бесплатный тариф |
| Argos Translate | Опционально | Полностью офлайн, бесплатно, без ключей; качество ниже |
| Внешний файл (LLM-чат) | Всегда доступен | Бесплатно через любой чат-бот; сценарий F |

Добавление нового провайдера не трогает остальное приложение. Пакеты формируются с учётом лимитов каждого API (размер запроса, скорость), с автоповтором при сбоях и возможностью продолжить прерванное. API-ключи хранятся в защищённом хранилище Windows (Credential Manager), никогда — в открытых файлах настроек или базе. Неофициальные «бесплатные» обёртки веб-переводчиков не используются: они нестабильны и нарушают условия сервисов.

## 13. Форматы обмена с внешним миром

### 13.1. Файл-задание для LLM: JSONL (основной для сценария F)

Одна строка файла — одна строка перевода:

```
{"id":"u0001","key":"rule_epe_fullface_helmets","type":"rule","source":"⟦T1⟧EPE: Enclosed Helmets","target":"","note":"⟦T1⟧ — иконка, не трогать"}
{"id":"u0002","key":"setting_default_epe_fullface_helmets_desc","type":"desc","source":"Characters are allowed to wear helmets...","target":""}
```

Правила импорта — строгие: менять можно только `target`; `id`, `key`, `source` обязаны совпадать с базой; потерянные или задвоенные `id` блокируют импорт целиком; повреждённые маркеры блокируют конкретную строку; если исходник мода успел обновиться после экспорта — строка отклоняется с объяснением. Вместе с файлом генерируется готовый промпт-инструкция для LLM (что переводим, глоссарий, «маркеры не трогать», «верни файл в том же формате»).

### 13.2. XLIFF 2.1 (для совместимости с миром профессиональной локализации)

Стандартный двуязычный формат, который понимают переводческие программы (OmegaT, Smartcat и др.) и профессиональные переводчики. Экспорт/импорт с теми же строгими проверками. Появляется на этапе 4 вместе с JSONL; кто им пользуется — переводчики-энтузиасты.

### 13.3. Человекочитаемый предпросмотр (Markdown/TXT)

Формат «файл → ключ → текст», который клиент описал изначально, остаётся как **предпросмотр и черновик для чтения** — но не как формат обратного импорта: у него нет защиты от искажений (LLM переставит строки, потеряет кавычки — и импорт превратится в лотерею). Надёжный обратный путь — только JSONL/XLIFF. Это осознанное отступление от первоначальной идеи в пользу надёжности; удобство сохраняется — JSONL так же легко скармливается любому чат-боту.

## 14. Интерфейс: карта экранов

Принцип интерфейса: **сначала статус, потом действие**. Пользователь всегда видит, в каком состоянии его библиотека, и каждая цифра кликабельна и ведёт к списку конкретных строк.

### 14.1. Главный экран — «Библиотека»

```
┌─────────────────────────────────────────────────────────────────┐
│  Модов установлено: 186      Обновились с прошлого визита: 8    │
│  Без русского: 57 ▸          Требуют обновления перевода: 5 ▸   │
│  Русский неполный: 32 ▸      Ошибки в файлах модов: 3 ▸         │
│                                          [Перевести все… ]      │
├─────────────────────────────────────────────────────────────────┤
```

### 14.2. Карточка мода

Вкладки:

- **Обзор** — название, ID, ссылка на Workshop, версии, языки с процентами полноты, крупные кнопки главных действий («Создать русский перевод» / «Доперевести N строк» / «Восстановить перевод»).
- **Строки** — главная рабочая таблица (см. 14.3).

- **Диагностика** — дубликаты, битые строки, расхождения имени/заголовка, «лишние» ключи.
- **Экспорт/Импорт** — JSONL/XLIFF/предпросмотр, импорт с отчётом.
- **Настройки проекта** — исходный и целевой языки, режим записи (внутрь мода / патч-мод), режим сборки (дельта/полный), глоссарий мода, имя патч-мода.

### 14.4. Уведомления

Центр уведомлений внутри приложения (значок с числом). Типы: «мод обновился, перевод отстал» (важное), «мод обновился, локализация не тронута» (тихое), «импорт завершён с N отклонёнными», «сборка патча прошла/не прошла». Системные всплывающие уведомления Windows — опционально, по умолчанию выключены. Никаких уведомлений ради уведомлений.

### 14.5. Мастер пакетного перевода (сценарий I)

Шаги: выбор модов (по умолчанию — все без русского) → провайдер → **смета** (строк всего, закроется ванилью/памятью, пойдёт в API, примерная стоимость) → выполнение с очередью и паузой → итоговый отчёт со ссылками на карточки.

## 15. Что и где хранится

Простыми словами — три места:

1. **База приложения** (одна папка в профиле пользователя, внутри — база SQLite и архив снимков): каталог модов, снимки локализаций по версиям, проекты перевода, статусы строк, память переводов, глоссарии, журнал операций. Её резервное копирование = сохранение всего труда. В настройках — кнопка «Создать резервную копию базы» и «Восстановить».
2. **Записанные переводы** — русские папки внутри модов мастерской и/или патч-моды в `Documents\Paradox Interactive\Crusader Kings III\mod\` — рабочий результат, который видит игра. Полностью восстановимы из базы в любой момент («Восстановить/Пересобрать»).
3. **Файлы автора** в папке Workshop — только читаются, никогда не изменяются и не удаляются.

Технические таблицы базы (для разработчика): mods, mod_snapshots, localization_files, localization_entries, translation_projects, translation_units, translation_memory, glossary_terms, translation_jobs, generated_outputs, diagnostics. Ключевые поля translation_units: ключ, языковая пара, исходный текст на момент перевода + его хеш, текущий перевод + хеш на момент последней сборки, статус, провайдер, отметка проверки, время.

Снимки хранят разобранные ключи и значения плюс сжатые копии изменившихся файлов — этого достаточно для трёхстороннего сравнения и восстановления, без хранения полных копий всего подряд.

## 16. Технологический стек (кратко)

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12+ | Быстро развивать специфический парсер, есть SDK всех переводчиков |
| GUI | PySide6 (Qt) | Полноценный нативный Windows-интерфейс, таблицы на десятки тысяч строк |
| База | SQLite | Один файл, нулевое администрирование, достаточно навсегда |
| Сеть | httpx | Современный HTTP-клиент с автоповторами |
| Слежение за папками | watchdog + debounce | Steam пишет файлы сериями — ждём затишья, потом один анализ |
| Ключи API | keyring (Windows Credential Manager) | Не храним секреты открытым текстом |
| Сборка | PyInstaller | Один .exe-установщик, Python пользователю не нужен |

Архитектура: `core/` (сканер, парсер, анализ, снимки, diff, форматы, сборщик) + `providers/` (переводчики) + `cli/` + `desktop/` + `tests/` с корпусом реальных модов. Ядро не знает про GUI — это проверяется тем, что все операции доступны из командной строки.

## 17. Дорожная карта

Каждый этап заканчивается работающим продуктом, а не «заделом». Клиент планирует собирать продукт целиком по этому документу (генерация «одним промптом»), поэтому этапы — это прежде всего порядок **приёмки**: в какой последовательности проверять, что фундамент надёжен, даже если код появился весь сразу.

| Этап | Что появляется | Критерий готовности («демо клиенту») |
|---|---|---|
| **1. Парсер + корпус** | Чтение/запись файлов локализации без потерь | На корпусе из 30+ реальных модов: прочитали—записали → байт в байт. Отчёт по одному моду в консоли |
| **2. Сканер (только чтение)** | Поиск Steam, всех модов, языков, полноты, диагностика | Консольный отчёт по всей библиотеке: «57 модов без RU», список пропущенных строк любого мода |
| **3. Снимки + сравнение** | База, история версий, определение новых/изменённых/удалённых строк | Обновить любой мод в Steam → приложение точно называет, что изменилось |
| **4. MVP: экспорт/импорт + запись перевода + первый GUI** | JSONL/XLIFF, строгий импорт, запись внутрь мода и сборка патч-модов, восстановление после обновлений, главный экран и карточка мода | **Сквозной сценарий B руками клиента**: мод без RU → экспорт → перевод в LLM-чате → импорт → запись в мод → русский текст в игре |
| **5. Встроенный перевод** | Провайдеры волны 1 (Google, Yandex, DeepL), затем LLM; память переводов, ваниль CK3, глоссарий, редактор строк, пакетный режим | Сценарии B (через API), C, D, I целиком в GUI |
| **6. Продвинутое** | Плейсеты и порядок загрузки, конфликты модов между собой, объединённый пак, локальные моды, анализ error.log, экспорт автору, публикация в Workshop | По итогам обратной связи |

**MVP = конец этапа 4.** Уже без единого встроенного переводчика продукт решает главную боль: инвентаризация, точный diff после обновлений, безопасная запись перевода с восстановлением, бесплатный перевод через любой LLM-чат.

### Что сознательно НЕ делаем (по крайней мере до этапа 6)

- Не публикуем переводы в Workshop автоматически (юридика и этика: желательно согласие автора мода; функция появится позже как «мастер публикации» с напоминанием спросить автора).
- Не переводим ничего, кроме `localization` (названия событий в скриптах, картинки с текстом — вне рамок).
- Не делаем облачную синхронизацию и совместную работу нескольких переводчиков.
- Не поддерживаем другие игры Paradox (архитектура парсера это позволит позже — форматы у CK3/Stellaris/HOI4 родственные, — но фокус сейчас на CK3).
- Не встраиваем неофициальные бесплатные обёртки переводчиков.

## 18. Риски и как мы их гасим

| Риск | Вероятность | Защита |
|---|---|---|
| Steam стёр перевод в режиме «внутрь мода» (обновление или проверка целостности) | Гарантированно случается | Штатный цикл, а не авария: база — источник истины, автовосстановление не изменившихся строк + доперевод новых |
| Парсер портит редкий формат файла | Средняя | Тест «байт в байт» на растущем корпусе; нераспознанные строки не трогаем |
| Paradox изменит формат/список языков | Низкая | Языки читаем из игры; парсер терпим к незнакомому |
| Steam изменит структуру папок/ACF | Низкая | ACF — вспомогательный сигнал, основа — сами папки и API |
| LLM ломает файл при внешнем переводе | Высокая | Строгий импорт: битые строки отклоняются точечно, отчёт |
| Пользователь потерял базу | Средняя | Кнопка резервной копии; манифест внутри патч-модов восстанавливает связь и статусы; переводы из папок модов читаются обратно как «перевод без истории» |
| Тарифы/лимиты API изменятся | Средняя | Смета до запуска; несколько провайдеров; бесплатный путь через JSONL всегда есть |
| Конфликт с чужим переводом того же мода из Workshop | Средняя | Диагностика на этапе 6: «этот мод уже переопределяется другим модом»; до того — приоритет решается порядком загрузки |

## 19. Метрики успеха (как поймём, что получилось)

- Время от установки приложения до первого русского текста в игре: **< 30 минут** (включая перевод через LLM-чат).
- Обработка обновления мода (заметить → доперевести → пересобрать): **< 5 минут** активного времени.
- Ноль случаев изменения или удаления файлов автора мода (мы только добавляем свои) и ноль потерь пользовательских переводов, включая стёртые обновлениями Steam (база + резервные копии + история).
- Доля строк, закрытых бесплатно (ваниль + память переводов) при переводе типичного мода: ориентир **15–30 %** — проверим на реальных данных.
- Клиентская проверка: пользователь без подсказок проходит сценарии B и D.

## 20. Решения, принятые клиентом (26.07.2026)

Зафиксированы по итогам обсуждения; отражены во всех разделах документа.

1. **Куда пишется перевод:** по умолчанию — прямо внутрь мода, добавленной папкой `russian` (раздел 5.1). Отдельный патч-мод остаётся переключаемым режимом (раздел 5.2). Цена решения (Steam стирает файлы при обновлении) оплачена автоматическим восстановлением из базы.
2. **Фоновая проверка обновлений при закрытом приложении:** не делаем. Проверка — при запуске приложения и вручную по кнопке.
3. **Способ перевода — всегда явный выбор пользователя:** либо встроенный перевод в приложении, либо выгрузка цельного файла-задания → перевод в любой нейросети → импорт обратно, и программа сама создаёт корректные файлы локализации. Оба пути равноправны и видны в интерфейсе рядом.
4. **Провайдеры:** волна 1 — Google, Yandex, DeepL; волна 2 — LLM по API. Поскольку продукт собирается целиком по этому документу, в спецификации описано всё сразу.
5. **Языки:** целевые языки не ограничены русским — выбор в интерфейсе с первого дня; исходный язык — любой, не только английский (приложение само предлагает самый полный язык мода как источник).

## 21. Глоссарий документа

| Термин | Значение |
|---|---|
| **Мод-источник** | Оригинальный мод из мастерской Steam, который переводим |
| **Режим «внутрь мода»** | Запись перевода добавленной папкой прямо в папку мода мастерской; файлы автора не изменяются |
| **Патч-мод** | Отдельный локальный мод, создаваемый приложением, содержащий только перевод |
| **Проект перевода** | Связка «мод-источник + пара языков» со всеми строками, статусами и историей |
| **Снимок** | Сохранённое состояние локализации мода на момент конкретной версии |
| **Ключ** | Идентификатор строки в файле локализации (например `rule_epe_makeup_options`) |
| **Дельта** | Режим сборки, при котором записываются только недостающие/исправленные строки |
| **Память переводов** | База ранее сделанных пар «оригинал → перевод», переиспользуемых автоматически |
| **Глоссарий** | Словарь обязательных соответствий терминов (Realm → Держава) |
| **Ваниль** | Локализация самой игры CK3 без модов |
| **Плейсет** | Набор и порядок загрузки модов в лаунчере CK3 |
| **JSONL / XLIFF** | Форматы файлов для обмена переводами с LLM и переводческими программами |
| **Лаунчер** | Программа запуска CK3, где включаются моды |
